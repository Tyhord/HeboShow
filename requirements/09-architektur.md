# Architektur

> This documentation has been fully generated by an AI.

Zwei getrennte Programme im LAN, kein Docker. Internet braucht nur der optionale
KI-Client (GitHub Copilot oder OpenAI) auf seinem eigenen PC:

* **`hebo-server/`**: einzige Quelle der Wahrheit. Kamera, Tracking, Spielregeln, Effekte,
  Balancing, Spieler und alle gespeicherten Daten. Läuft nur als Konsole.
* **`hebo-client/`**: Anmeldung, Fenster und Seiten. Rechnet nichts am Spiel, zeigt nur den
  Zustand des Servers und schickt Aktionen. Beliebig oft auf beliebigen Geräten. Mit dem
  Namen `KI` wird er zum KI-Client: ohne Fenster, mit KI-Modell und Bluetooth zum eigenen Roboter.

## Bausteine Server

| Modul | Aufgabe |
| --- | --- |
| `hebocon/__main__.py` | Start: Logging, Adapterwahl, Konsolen-Banner, Suche, uvicorn auf der gewählten IP |
| `hebocon/network.py` | Netzwerkadapter auflisten, in der Konsole wählen, in `data/network.json` merken, überwachen |
| `hebocon/config.py` | Alle Einstellungen (`HEBOCON_`), Grenzen der Balancing-Werte |
| `hebocon/app.py` | Ablaufsteuerung, Phasen, Aktionen, Zustand; Balancing laden und in `data/balancing.json` speichern, Intro-Schalter in `data/match.json` |
| `hebocon/lobby.py` | Rollen, Tokens, Moderationspasswort, Spielerplätze; gespeichert in `data/lobby.json` |
| `hebocon/discovery.py` | Antwortet auf UDP-Suchanfragen der Clients |
| `hebocon/camera.py` | Kamera-Thread, hält nur das neueste Bild |
| `hebocon/vdoninja.py` | VDO.Ninja-Empfang per aiortc (Signalisierung, WebRTC, Dekodierung) |
| `hebocon/arena.py` | Ecken, Entzerrung, Leerbild, Vordergrund |
| `hebocon/segmenter.py` | EdgeTAM (optional): Maske bei der Registrierung, Video-Gedächtnis für den Schiedsrichter |
| `hebocon/tracking.py` | Zwei Roboter-Plätze aus der Leerbild-Differenz, Aussehens-Abgleich, EdgeTAM-Schiedsrichter |
| `hebocon/game.py` | HP-Regeln, reine Logik ohne Bild |
| `hebocon/server.py` | Starlette: Anmeldung, Rechte, REST-Aktionen, WebSocket, Steckbriefbilder in `data/media/`, Meme-Dateien aus `memes/` |
| `hebocon/library.py` | Soundboard: Ordner `memes/` überwachen, Index `data/soundboard.json` mit Kategorien und Reihenfolge (die feste Rubrik „Uncategorized“ wird nur angezeigt, nie gespeichert), Dateityp am Inhalt prüfen, Upload, Freistellen im Hintergrund |
| `hebocon/download.py` | Medien-Import per URL: nur öffentliche http(s)-Ziele, verbindet zur geprüften IP, folgt Weiterleitungen mit erneuter Prüfung |
| `hebocon/memes.py` | Green Screen erkennen und entfernen (VP9 mit Alpha), Ergebnis prüfen, Original ersetzen |
| `greenscreen.py` | Kommando: alle Videos in `memes/` freistellen |

## Bausteine Client

| Datei | Aufgabe |
| --- | --- |
| `client.py` | Server suchen oder IP abfragen, `name:` und Passwort abfragen, anmelden, Seiten lokal ausliefern, Ansicht der Bedienung unter `/prefs` merken, pywebview-Fenster öffnen, Verbindung überwachen; bei `KI`/`AI` stattdessen `pilot.py` starten |
| `pilot.py` | KI-Client: Zugang (Copilot oder OpenAI-Schlüssel) und Modellwahl, Bluetooth zum Roboter, WebSocket mit Bild, Lagebild und Bild ans Modell, Werkzeuge, Taktik-Regler, Status an den Server |
| `web/common.js` | Serveradresse und Token aus der URL, `api()`, `connect()`, Zeichnen |
| `web/stage.html` | Bühne; beim Spieler zusätzlich eigener Ulti-Knopf und Wenig-HP-Vignette |
| `web/operator.html` | Bedienung |
| `client.json` | Letzter Server, Tokens je Server und Rolle, Vorgaben des KI-Clients, Ansicht der Bedienung |

## Threads Server

| Thread | Arbeit |
| --- | --- |
| `camera` | liest Bilder, überschreibt das neueste. Bei VDO.Ninja läuft darin eine asyncio-Schleife. |
| `process` | pro neuem Bild: Tracking, Spiel-Tick, Paket bauen |
| `model-load` | lädt EdgeTAM einmal beim Start, nur wenn eingeschaltet |
| `edgetam` | nur mit EdgeTAM: prüft ab und zu ein Bild, das Tracking wartet nie darauf |
| Hintergrund-Aktionen | Scan, Segmentierung bei der Registrierung |
| `discovery` | beantwortet UDP-Suchanfragen aus dem Netz des gewählten Adapters |
| `netwatch` | prüft alle 5 s, ob der gewählte Adapter noch verbunden ist, und warnt in der Konsole |
| `memes` | schaut alle 2 s in `memes/`, übernimmt neue und entfernt verschwundene Dateien |
| `keyer` | arbeitet hochgeladene Videos mit „Remove green screen“ nacheinander ab, jeweils in einem eigenen Prozess mit niedriger Priorität, damit das Tracking nicht leidet |
| Hauptthread | uvicorn, Aktionen laufen per `asyncio.to_thread` |

Gemeinsamer Zustand ist durch eine Sperre in `app.py` geschützt, die Lobby durch eine
eigene in `lobby.py`.

## Datenfluss

```
Kamera ─► process ─► Tracker.update ─► Game.tick ─► Paket (Zustand + JPEG)
                                                           │
                                                           ▼
                                   WebSocket ─► alle Clients (Bühne, Bedienung, Spieler)
Bedienung/Spieler ─► POST /api/<aktion> (Bearer-Token) ─► Rechte prüfen ─► App.act
Client-Start ─► UDP-Suche ─► POST /lobby/join ─► Token ─► Fenster mit ?server=…&token=…
WebSocket (frames=1) ─► KI-Client ─► Modell (Bild + Lage) ─► Werkzeuge ─► Bluetooth ─► Roboter
                                                                   └─► POST /api/ulti, say, ai_status
```

Bild und Zustand reisen **in einer Nachricht**. So passen Umrisse immer genau zum Bild.
Die Seiten zeichnen nur, gerechnet wird im Server.

## KI-Client

Eine asyncio-Schleife mit drei Aufgaben: Die WebSocket-Aufgabe hält das neueste Paket.
Die schnelle (20×/s) schätzt die Fahrtrichtung, fährt die gewählte Taktik und hält außerhalb
des Kampfs oder ohne frisches Paket (1 s) an. Die langsame schickt etwa alle `turn_s` Bild
und Lage an das Modell und führt die Werkzeugaufrufe aus; Ulti und Sprüche gehen als Aktionen
an den Server, der sie nach denselben Regeln prüft wie bei Menschen.
