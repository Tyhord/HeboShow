# Schnittstellen

> This documentation has been fully generated by an AI.

Der Server lauscht nur auf der IPv4-Adresse des beim Start gewählten Netzwerkadapters, Port
`HEBOCON_PORT` (8765). Ist `HEBOCON_HOST` gesetzt, gilt stattdessen diese Adresse. Über
`127.0.0.1` ist der Server dann nicht erreichbar, auch nicht vom eigenen Rechner. Die Seiten liefert nicht der Server, sondern jeder Client selbst über einen
lokalen Mini-Server; der Server erlaubt deshalb Anfragen jeder Herkunft (CORS).

## Suche im LAN

Der Client schickt `HEBOCON?` per UDP-Broadcast an Port `HEBOCON_DISCOVERY_PORT` (8766).
Der Server antwortet `{"app": "hebocon", "port": 8765, "id": "<server-id>", "ip": "<adresse>"}`,
aber nur Absendern im Netz des gewählten Adapters oder auf demselben Rechner. Der Client
verbindet sich mit `ip`, sonst mit der Absenderadresse der Antwort. Die `id`
bleibt über Neustarts gleich (in `data/lobby.json`), damit gespeicherte Tokens zum
richtigen Server passen.

## Anmeldung

| Pfad | Inhalt |
| --- | --- |
| `GET /lobby/hello` | `{"app": "hebocon", "id", "port"}`; prüft, ob unter einer Adresse ein Server läuft |
| `POST /lobby/join` | Körper `{"name", "password"?, "token"?}`. Antwort `{"ok", "token", "role", "name", "slot"}` oder 400 mit `{"ok": false, "code", "message"}` |
| `POST /lobby/leave` | Spieler gibt seinen Platz frei. Name und Token bleiben gespeichert. |

* `name` `stage` → Rolle `stage`. `mod`/`moderator` → Rolle `moderator`, nur mit richtigem
  `password` (`HEBOCON_MOD_PASSWORD`, nur auf dem Server). Jeder andere Name → `player`
  auf dem ersten freien Platz 1 oder 2, höchstens 24 Zeichen.
* `code`: `password` (falsches Passwort), `taken` (Name spielt schon auf einem anderen
  Gerät), `full` (beide Plätze belegt), `invalid` (sonst).
* Wer sein altes `token` mitschickt, bekommt denselben Platz zurück. Ein neuer Name mit
  demselben Token benennt den Platz um, statt einen zweiten zu belegen.
* Alle weiteren Anfragen tragen `Authorization: Bearer <token>`.

## Rechte

| Rolle | Darf |
| --- | --- |
| `moderator` | alle Aktionen, Medien hochladen, umbenennen, löschen |
| `player` | `ulti` (immer für den eigenen Platz, `player` im Körper wird ignoriert), `cue` mit `kind: "ended"` |
| `stage` | `cue` mit `kind: "ended"` |

Lesen (`GET /media…`) geht ohne Token. Ohne gültiges Token antwortet der Server 401, mit
fehlendem Recht 403 und `{"ok": false, "message"}`.

## Medien

| Pfad | Inhalt |
| --- | --- |
| `POST /media` | Datei hochladen: roher Körper, `Content-Type` der Datei, Kopf `X-Name` (URL-kodiert). Ohne `X-Board: 1` ein Steckbriefbild (`/media/<key>`, bis zum Neustart). Mit `X-Board: 1` eine Soundboard-Kachel in `memes/`; `X-Key: 1` stellt ein Video zusätzlich frei. Antwort `{"ok", "url", "name", "mime", "cutout", "processing"}`, höchstens 100 MB |
| `GET /media` | Soundboard-Kacheln in Board-Reihenfolge: `[{"url", "name", "mime", "cutout", "processing"}]`; `cutout: true` heißt freigestelltes Video mit Alphakanal, die Bühne zeigt es ohne Rahmen; `processing: true` heißt, das Grün wird gerade entfernt |
| `GET /media/<key>` | Steckbriefbild abrufen |
| `GET /memes/<datei>` | Meme-Datei abrufen (nur Dateien, die im Soundboard stehen) |
| `PATCH /memes/<datei>` | Kachel umbenennen, Körper `{"name"}` |
| `DELETE /memes/<datei>` | Kachel und Datei löschen; während des Freistellens nicht möglich |

`url` ist relativ zum Server (`/memes/<datei>` URL-kodiert); die Seiten setzen die Serveradresse davor.

## Aktionen

`POST /api/<aktion>` mit JSON-Körper. Antwort `{"ok": true}` oder Status 400 mit
`{"ok": false, "message": "…"}`. Die Meldung erscheint auch in `message` im Zustand.

| Aktion | Daten | Wirkung |
| --- | --- | --- |
| `camera` | `{"source": "0"}` | Kameraquelle wechseln |
| `corners` | `{"points": [[x,y] ×4]}` | Arena-Ecken in Bildpixeln setzen |
| `reset_arena` | – | Ecken verwerfen, zurück zur Kalibrierung |
| `new_battle` | – | Neue Registrierung, beide Roboter werden automatisch erkannt |
| `pick` | `{"x", "y", "slot"}` | Roboter unter dem Klick dem Slot 1 oder 2 zuordnen |
| `start` | `{"names": ["…", "…"]}` | Kampf starten: Intro, dann VS-Bildschirm (`ready`); in `ready` startet es den Countdown |
| `spawn` | `{"kind": "obstacle" \| "powerup"}` | Objekt von Hand erzeugen |
| `shrink` | – | Arena schrumpfen lassen (nur im Kampf, einmal) |
| `hud` | `{"on": bool}` | Kampf-HUD auf der Bühne ein- oder ausblenden |
| `profile` | `{"player": 1 \| 2, "name", "image", "team", "weight", "height", "slogan"}` | Steckbrief für den VS-Bildschirm; alle Felder Text, `image` ist eine `/media/…`-URL. Der Name gilt nur außerhalb eines laufenden Kampfs. |
| `cue` | `{"kind": "media" \| "stop" \| "ended", "media"?: {"url", "name", "mime", "cutout"?}, "id"?}` | `media` startet ein Medium oder schaltet ein laufendes gleicher URL zwischen Pause und Fortsetzen um; `stop` beendet alle; `ended` meldet die Bühne, wenn Meme `id` zu Ende ist |
| `ko` | `{"player": 1 \| 2}` | Roboter sofort auf 0 HP, Kampf endet wie bei einem echten K.O. (nur im Kampf) |
| `ulti` | `{"player": 1 \| 2}` | Laser-Ulti des Roboters auslösen (nur im Kampf, einmal, wenn geladen) |
| `abort` | – | Kampf abbrechen |
| `balancing` | `{"key": "<feld>", "value": zahl}` | Einen Balancing-Wert setzen (Felder wie in `balancing` im Zustand); gilt sofort und wird in `data/balancing.json` gespeichert. Unbekanntes Feld, keine Zahl oder außerhalb der Grenzen → 400. |
| `balancing_reset` | – | Alle Balancing-Werte auf `.env`/Standard zurück, `data/balancing.json` wird gelöscht |
| `name` | `{"player": 1 \| 2, "name"}` | Roboternamen setzen; im laufenden Kampf gilt er ab dem nächsten. Meldet sich der Spieler neu an, gilt wieder sein Lobby-Name. |
| `kick` | `{"slot": 1 \| 2}` | Spieler vom Platz nehmen. Sein Name bleibt gespeichert, der Platz wird frei. |

Während `busy` gesetzt ist, sind nur `camera`, `abort`, `spawn`, `shrink`, `hud`, `profile`,
`cue`, `ko`, `ulti`, `balancing`, `balancing_reset`, `name` und `kick` erlaubt.

## WebSocket `/ws?token=<token>&frames=0|1`

Ohne gültiges Token schließt der Server sofort mit Code `4401`; die Seite meldet „neu
anmelden“ und versucht es alle 3 s weiter. Bei anderen Abbrüchen verbindet sie sich nach
1 s neu und bekommt sofort den aktuellen Zustand. `frames=0` lässt das JPEG weg (für
Seiten ohne Kamerabild; die Bühne nutzt `frames=1`, auch beim Spieler).

Binärnachricht pro Kamerabild:

```
[4 Byte Länge N, little endian][N Byte JSON-Zustand][JPEG]
```

Ohne Kamerabild wird etwa alle 0,25 s nur der Zustand geschickt, `frame` ist dann `null`
und das JPEG fehlt. Langsame Empfänger verlieren alte Bilder, sie stauen sich nicht.

## Zustand

Alle Koordinaten in **Pixeln des Originalbildes** (`frame.w` × `frame.h`).

| Feld | Inhalt |
| --- | --- |
| `phase` | `arena`, `register`, `intro`, `ready`, `countdown`, `fight`, `finished` |
| `intro` | nur in `intro`: Sekunden bis zum VS-Bildschirm, sonst `null` |
| `countdown` | nur in `countdown`: Sekunden bis zum Kampfbeginn, sonst `null` |
| `elapsed` | Kampfzeit in Sekunden ab Ende des Countdowns, steht beim Ende still; `null` vor dem Kampf |
| `hud` | Ob die Bühne das Kampf-HUD zeigt |
| `vs` | Ob die Bühne den VS-Bildschirm zeigt: genau in Phase `ready` |
| `names` | Die zwei Roboternamen (für den VS-Bildschirm) |
| `profiles` | Zwei Steckbriefe `{"image", "team", "weight", "height", "slogan"}` für den VS-Bildschirm |
| `memes` | Liste `{id, media, paused, played, x, y, tilt}`. `played` ist die gespielte Zeit in s, `x`/`y` (0–1) der Anteil am freien Platz, damit das Meme auf jeder Bühnengröße ganz sichtbar bleibt. Eine neu geöffnete Bühne steigt bei `played` ein. |
| `battle` | Zähler, steigt bei jedem Start. Trennt Ereignisse verschiedener Kämpfe. |
| `board` | `{"rev", "keying"}`: `rev` steigt, sobald sich die Soundboard-Liste ändert (dann `GET /media` neu laden); `keying` ordnet der `url` jeder gerade freigestellten Kachel den Fortschritt 0–1 zu |
| `message` | Klartext für die Bedienung |
| `busy` | Name der laufenden Hintergrundarbeit oder `null` |
| `camera` | `source`, `error` |
| `tracking` | `fps` (fertige Tracking-Bilder pro Sekunde, `0` ohne Tracking), `latency_ms` (Aufnahme bis Ergebnis), `error` (letzter Tracking-Fehler oder `null`) |
| `model` | EdgeTAM: `enabled`, `ready`, `error`, `device` (GPU-Name oder CPU), `corrections` (Identitäts-Korrekturen durch den Schiedsrichter) |
| `arena` | `null` oder `corners`, `size` (Arena in Einheiten) |
| `proposal` | in `register`: `slot`, `contour` der beiden erkannten Roboter |
| `robots` | `id`, `name`, `present`, `hp`, `max_hp`, `outside`, `center`, `contour`, `ulti` (`charge` 0–1, `ready`, `used`) |
| `contact` | beide Roboter berühren sich gerade |
| `items` | `id`, `kind`, `center`, `poly`, `armed`, `ttl` |
| `shot` | `null` oder der zielende Laser: `player`, `from`, `to`, `left` (Sekunden bis zum Schuss), `aim` (Zieldauer) |
| `zone` | `null` oder die 4 Eckpunkte der erlaubten Fläche, während die Arena schrumpft |
| `balancing` | Aktuelle Spielregel-Werte, Schlüssel wie die `HEBOCON_`-Variablen ohne Präfix in Kleinbuchstaben (`start_hp`, `collision_damage`, …, `shrink_duration_s`) |
| `lobby` | `{"players": [{"slot", "name", "online"}], "online": {"stage", "moderator", "player"}}`: belegte Spielerplätze und Zahl offener Verbindungen je Rolle |
| `events` | die letzten 30 Ereignisse, siehe unten |
| `winner` | Name des Siegers oder `null` |
| `finished` | Kampf vorbei |
| `frame` | `null`, vor den Ecken `{"w", "h", "kind": "camera"}` des Originalbildes, danach `{"w", "h", "kind": "arena", "pad"}`: Feldgröße in Arena-Einheiten; das Bild zeigt `pad` Einheiten Rand ringsum, Koordinaten beginnen trotzdem in der Feldecke |

## Ereignisse

Jedes hat `id` (fortlaufend pro Kampf) und `type`. Die Bühne spielt jedes nur einmal ab.

| `type` | Weitere Felder |
| --- | --- |
| `collision` | `player`, `amount`, `pos` |
| `obstacle` | `player`, `amount`, `pos` |
| `powerup` | `player`, `amount`, `pos` |
| `ringout_start`, `ringout_end` | `player` |
| `ringout_ko` | `player` (ganz aus der Arena gefahren, auf 0 HP) |
| `shrink` | – (Arena beginnt zu schrumpfen) |
| `spawn` | `kind`, `pos` |
| `ulti_aim` | `player` (Schütze), `from`, `to` (Arena-Einheiten) |
| `ulti_fire` | `player` (Schütze), `hit`, `at` (Trefferpunkt oder `null`), `from`, `to` |
| `ulti` | `player` (getroffen), `amount`, `pos` |
| `ko` | `players` (auf 0), `winner` (id oder `null`) |
