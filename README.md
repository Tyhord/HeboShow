# Hebocon Battle Vision

> This documentation has been fully generated by an AI.

Virtuelle Kampfarena für Hebocon. Eine Kamera filmt die Arena, die App erkennt zwei
Roboter, verfolgt sie, führt HP und zeigt Effekte für das Publikum.

* 100 HP pro Roboter, Ringout kostet 5 HP/s, ganz hinausfahren ist K.o.
* Kollisionen, Hindernisse (−30 HP), Power-ups (+25 HP), schrumpfende Arena per Knopf
* Jedes Bild wird vorher auf die Arena entzerrt und zugeschnitten; außerhalb wird nichts
  erkannt
* Roboter werden über die Differenz zum Leerbild verfolgt, 30 Bilder/s ohne GPU;
  EdgeTAM kann optional nebenher die Identitäten prüfen
* Ein **Server** (`hebo-server/`) rechnet alles: Kamera, Tracking, HP, Effekte, Balancing,
  Spieler und gespeicherte Daten. Beliebig viele **Clients** (`hebo-client/`) im selben
  LAN zeigen Bühne (beim Spieler mit eigener Ulti) oder Bedienung. Internet ist nicht nötig.

## Start

Windows, Python 3.12 auf jedem Gerät. Beim ersten Start installiert jede `start.bat` ihre
Pakete selbst ins eigene `.venv`.

### Server (ein Rechner, an dem die Kamera hängt)

Doppelklick auf `hebo-server\start.bat`. Hat der Rechner mehrere Netzwerkadapter, zeigt die
Konsole zuerst eine nummerierte Liste mit Name, IPv4-Adresse und Status. Nummer eingeben,
und der Server ist nur über diesen Adapter erreichbar und auffindbar. Die Wahl wird gemerkt
und beim nächsten Start nach 10 s oder mit Enter wieder genommen; eine andere Nummer wechselt.
Danach zeigt die Konsole Adapter, Adresse für Clients, Port, Kamera und das laufende Protokoll
(Anmeldungen, Verbindungen, Aktionen, Fehler).
Argumente werden durchgereicht, z.B. `start.bat --camera 1` oder
`start.bat --camera C:\pfad\kampf.mp4`.

Beim ersten Start fragt die Windows-Firewall nach `python.exe`: für **private Netzwerke**
erlauben. Gebraucht werden TCP 8765 (Spiel) und UDP 8766 (automatische Suche).

Einstellungen: `hebo-server\.env.example` nach `hebo-server\.env` kopieren und anpassen,
z.B. `HEBOCON_MOD_PASSWORD` (Standard `admin`).

### Client (beliebig viele Geräte, auch derselbe Rechner)

Den Ordner `hebo-client` auf das Gerät kopieren und `start.bat` doppelklicken. Der Client
sucht den Server im LAN. Findet er keinen, fragt er nach der IP (die steht in der
Server-Konsole). Der letzte Server wird in `client.json` gemerkt. Fest vorgeben geht mit
`start.bat --server 192.168.0.10`.

Dann fragt er `name:`:

| Eingabe | Rolle | Fenster |
| --- | --- | --- |
| `stage` | Bühne | Kampfansicht, beliebig viele gleichzeitig |
| `mod` oder `moderator` | Moderation, fragt nach dem Passwort | Kampfansicht und Bedienung |
| jeder andere Name | Spieler 1 bzw. 2 | Kampfansicht mit eigenem Ulti-Knopf unten mittig (Klick oder Leertaste) und roter Vignette bei wenig HP |

Spielernamen sind eindeutig (Groß-/Kleinschreibung egal) und werden zum Roboternamen.
Sind beide Plätze belegt, bietet der Client an, als Bühne zu verbinden. Wer denselben
Namen auf demselben Gerät wieder eingibt, bekommt seinen Platz zurück. Beim Schließen
gibt ein Spieler seinen Platz frei; die Moderation kann Spieler im Tab „Roboter“ entfernen.

### KI-Client Quickstart

```powershell
cd C:\_dev\HeboShow_KI_Navigator_Nov_2026\hebo-server
.\.venv\Scripts\python -m hebocon --camera 0
```

```powershell
cd C:\_dev\HeboShow_KI_Navigator_Nov_2026\hebo-client
.\.venv\Scripts\python client.py --server <LAN-IP-aus-server>
```

Dann in der Client-Konsole:

```text
name: KI
```

Danach Startmodus (`manual` oder `auto`) und Controller-Endpunkt (`IP:Port`, Standard
`127.0.0.1:18899`) wählen. Der normale KI-Client braucht kein Copilot-/OpenAI-Setup mehr;
der Plan-B-Pilot läuft direkt.

Der Controller läuft separat, z. B.:

```powershell
cd C:\_dev\HeboShow_KI_Navigator_Nov_2026\HeboController\controller
python load.py 1 --listen-host 127.0.0.1 --listen-port 18899 --start-mode manual
```

Terminal-Steuerung während der Fahrt:

| Taste | Wirkung |
| --- | --- |
| `p` | Wechsel zwischen `manual` und `auto`; beim Wechsel schickt die KI einmal `stop` |

Im Modus `manual` gilt nur die lokale WASD-Tastatur im `load.py`. Im Modus `auto` sind lokale
WASD im Controller gesperrt; die KI schickt stattdessen UDP-Befehle (`drive`/`stop`).

Auto-Start:

* Ohne zweiten sichtbaren Roboter patrouilliert die KI zufällig und meidet Rand/Hindernisse.
* Mit Gegner wartet sie auf dessen Bewegung oder höchstens 10 s.
* Nach 10 s startet sie ebenfalls, vermeidet aber Angriffe, bis der Gegner sich erkennbar bewegt.

Der KI-Client arbeitet ohne Grafik-Fenster; alles läuft in der Konsole.

### Ohne start.bat

```powershell
cd hebo-server
python -m pip install --user uv
python -m uv sync
.venv\Scripts\python -m hebocon --camera 0

cd ..\hebo-client
python -m uv sync
.venv\Scripts\python client.py
```

EdgeTAM ist standardmäßig aus und lohnt sich nur mit NVIDIA-GPU. Einschalten mit
`HEBOCON_SEGMENT_ENABLED=true` in `hebo-server\.env`, nach `uv sync` die CUDA-Variante ins
`.venv` des Servers holen und danach nicht mit `uv run` starten, das stellt wieder auf CPU um:

```powershell
cd hebo-server
python -m uv pip install --reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -c "import torch; print(torch.cuda.is_available())"
```

Die Bedienung zeigt dann `EdgeTAM (GPU: …) prüft nebenher`.

Kamera als VDO.Ninja-Stream: `start.bat --camera "https://vdo.ninja/?view=meinStream"`.

`Hebocontroller/` ist ein eigenständiger Roboter-Controller und gehört nicht zu Server
oder Client.

## Ablauf in Kürze

Die Bedienung führt als Assistent durch vier Schritte:

1. Kamera wählen.
2. Arena leer räumen, „Ecken anklicken“; das Leerbild kommt automatisch.
3. Beide Roboter hinstellen, „Neuer Kampf“. Die App schlägt Roboter 1 vor: Namen, Enter.
   Dann Roboter 2: Namen, Enter.
4. „Kampf starten“. Hindernis, Power-up und „Arena schrumpfen“ per Knopf oder O, P, K.
