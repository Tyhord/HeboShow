## Die drei Regeln

1. **Fachlichkeit gehört nach `requirements/`.** Ändert sich Verhalten, wird die
   passende Datei dort im selben Schritt angepasst.

   nie per `pip install` ins System. Kein Docker.
3. **Kein Overengineering.** Passt etwas so wie es ist, bleibt es so.

## Starten und prüfen

Server und Client haben je ein eigenes `.venv`; Befehle im jeweiligen Ordner ausführen.

```powershell
# Einmalig
python -m pip install --user uv
cd hebo-server; python -m uv sync
cd ..\hebo-client; python -m uv sync

# Server: nur Konsole, kein Fenster
cd hebo-server; .venv\Scripts\python -m hebocon --camera 0
# Client: fragt nach name: (stage, mod, KI oder Spielername; KI = Copilot oder OpenAI fährt den Roboter)
cd hebo-client; .venv\Scripts\python client.py --server <LAN-IP aus der Server-Konsole>

# Prüfen (im Ordner hebo-server)
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m ruff check hebocon tests ..\hebo-client\client.py ..\hebo-client\pilot.py ..\hebo-client\tests
# KI-Client-Tests (im Ordner hebo-client)
.venv\Scripts\python -m pytest -q
```
